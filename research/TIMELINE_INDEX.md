## 🔗 UNIQUE ID SYSTEM

### Format & Structure

Each entry follows format: **[CATEGORY]-[SEQUENCE]**

**Categories**:
- **ACH** = Achievement/Milestone (e.g., ACH-001: Project Conception)
- **DEC** = Decision Made (e.g., DEC-001: Two-Stage Architecture)
- **CHAL** = Challenge/Problem (e.g., CHAL-001: Gradio Startup Failures)
- **SOL** = Solution Implemented (e.g., SOL-001: Robust Gradio Startup)
- **ARCH** = Architecture Design (e.g., ARCH-001: System Architecture)
- **DOC** = Documentation Created (e.g., DOC-001: Code Implementation Docs)

**Sequence Numbers**: 1, 2, 3, ... (chronological within category)

## 🎓 LESSONS LEARNED (Meta-Analysis)

### Technical Lessons

1. **Dependencies Matter**: Pin versions early ([SOL-002])
2. **Paths Are Fragile**: Use absolute paths or validate thoroughly ([SOL-003])
3. **Test Before Scaling**: Never run 17-hour job without small-scale test ([SOL-006])
4. **Deduplicate Aggregated Data**: Always expect duplicates from multiple sources ([CHAL-006])
5. **Interpretability > Performance**: Especially for medical AI ([SOL-008])

### Process Lessons

1. **Document Everything**: Forgotten problems become repeated mistakes ([SOL-009])
2. **Fail Fast**: Don't cling to failing approaches ([SOL-007])
3. **Expert Validation Early**: Should have consulted psychologists before building ([CHAL-002] lesson)
4. **Clean Repository**: Professional appearance aids adoption ([SOL-004])
5. **Unique IDs Enable Traceability**: Cross-referencing powerful for complex projects (this index)

### Communication Lessons

1. **Clear Status Tracking**: Team needs visibility into blockers
2. **Realistic Estimates**: "Quick fix" often takes days
3. **Quality Gates**: Don't proceed without validation
4. **Honest Reporting**: Acknowledge failures and pivots (these timelines)
